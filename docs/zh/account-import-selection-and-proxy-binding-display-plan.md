# 账号导入、手机适配、筛选全选及节点绑定显示修改方案

日期：2026-10-11  
状态：已实施（2026-10-11）。修改范围和验证记录见第 9 节。

## 1. 目标与适用范围

根据账号导入、账号管理及节点池截图，完成以下五项修改：

1. 修复导入预览中恢复邮箱提示与“跳过”复选框挤在一起的问题。
2. 导入弹窗顶部增加“跳过已有账号”，防止已有登录信息被更新。
3. 改善账号管理页面及其弹窗在手机端的布局。
4. 将批量操作区的“全选本页”改为“全选”，选择当前搜索、状态筛选匹配的所有账号，覆盖所有分页。
5. 保留已删除账号的历史节点绑定，但节点池显示的绑定数仅统计当前存在的账号。

本文替代 `account-import-batch-actions-and-proxy-mobile-plan.md` 中“全选采用本页范围”的规则；旧文档作为历史实施记录保留。本文未涉及的登录队列、自动恢复和导出格式继续沿用现有规则。

## 3. 导入预览布局

### 3.1 将操作与提示分开

“显式覆盖 / 跳过”单元格分为两个区域：

- 操作区：覆盖、跳过两个完整的复选框标签，使用 flex 布局及明确的 `gap`，允许整体换行。
- 提示区：恢复邮箱状态、凭据冲突等提示单独放在下一行，或放入独立状态列；与复选框保持间距。

建议采用“操作一行、提示下一行”，减少增加表格列造成的手机横向溢出。不能仅通过插入空格修复布局，也不能把恢复邮箱提示拼接进“跳过”的标签。必要时设置操作列最小宽度，并把横向滚动限制在表格内部。

### 3.2 恢复邮箱提示语义

当前预览返回的 `row.hasRecoveryEmail` 表示**本次导入行包含恢复邮箱**，并不表示目标账号此前已配置恢复邮箱。因此：

- 使用该字段时，文案改为“本次导入含恢复邮箱”。
- 如果需要展示“账号已配置恢复邮箱”，预览接口应另行返回目标账号的布尔状态，不返回邮箱明文。
- 恢复邮箱冲突继续单独提示，不能被普通状态提示覆盖。

### 3.3 验收标准

- 在桌面和手机宽度下，覆盖、跳过及恢复邮箱提示互不重叠，标签点击区域正确。
- 同时出现恢复邮箱提示和冲突提示时，内容仍完整可读。
- 长邮箱、英文文案和浏览器放大至 200% 时，允许换行，不挤压复选框。

## 4. 顶部“跳过已有账号”

### 4.1 交互规则

在导入弹窗顶部设置区域新增“跳过已有账号”，解析预览前即可设置，与“全部跳过”“全部覆盖”区分展示。

本文采用默认勾选，以实现保护已有登录信息的目标。辅助说明为：“仅导入新账号；已有账号不更新密码、验证器或恢复邮箱。”此默认值属于本次方案决定。

- 已有账号：CSV 已匹配目标账号，或验证器行已映射到现有账号。
- 勾选后，所有已有账号行的有效操作为跳过；新账号继续遵循逐行跳过及全部跳过规则。
- 此选项保持生效，直到用户取消勾选；重新解析、切换验证器映射后都重新计算保护范围。
- 受保护行显示“已有账号，已跳过”，禁用覆盖及取消跳过操作，避免页面显示与实际提交不一致。
- “全部覆盖”不能解除保护；若所有覆盖目标均受保护，则禁用该批量选项。
- “全部跳过”仍可跳过新账号；取消全部跳过也不能解除已有账号保护。
- 取消“跳过已有账号”后，解除策略保护，恢复原有逐行选择；覆盖仍须用户显式勾选，不自动开启。
- 错误行、不可导入的未变化行保持现有禁用和跳过限制。

建议将“逐行选择”和“保护策略导致的有效跳过”分开计算，避免取消顶部选项时错误恢复或覆盖用户此前的手工选择。提交中锁定设置；提交成功后的预览保持只读。新打开一次导入流程恢复默认保护状态。

### 4.2 后端保护

`POST /api/account-management/import/commit` 新增布尔字段 `skipExisting`，前端明确提交当前选项。旧调用未传字段时维持原有行为，以兼容现有客户端。

后端必须独立执行保护，不能只依赖前端将每行 `skip` 置为真：

1. 保留预览归属、有效期、行索引及重复行校验。
2. 逐行跳过、未变化行继续沿用原有处理。
3. `skipExisting === true` 时，对已匹配或映射的已有账号记为跳过，不调用 `edit()`，即使该行同时提交 `overwrite: true`。
4. 对预览时是新账号、提交时同邮箱账号已存在的 CSV 行，也不能更新已有账号；按跳过统计。需要依据提交时的账号状态检查，不能只看预览的 `accountId`。
5. 同邮箱匹配多个账号时，不将该行当成新账号创建；保护开启时跳过并提示，保护关闭时要求解决歧义后重新预览。
6. 保护关闭时，沿用凭据冲突的显式覆盖要求及凭据版本校验。

类型不正确的 `skipExisting` 应拒绝请求。跳过行计入现有 `skipped`，不得同时计入 `updated` 或创建登录任务。新账号仍根据全局自动登录设置决定是否入队。

### 4.3 验收标准

- 混合导入新账号和已有账号，默认只创建新账号。
- 已有账号即使密码、TOTP、恢复邮箱有差异，保护开启时这些字段及凭据版本均不变化，不触发凭据更新导致的任务失效。
- 顶部保护与全部覆盖同时开启，已有账号仍跳过。
- 取消保护后，可按原有规则显式更新已有账号。
- 验证器改映射、重新解析和预览后出现同邮箱账号，都不能绕过保护。

## 5. 账号管理手机适配

### 5.1 布局要求

建议以 `768px` 为主要切换断点，并检查 320、375、390、430、768 和 1280px 宽度。

- 顶部新增、上传、导入、导出和 VNC 按钮使用可换行布局；清除 Element Plus 相邻按钮默认左边距对换行首项的影响。
- 搜索与状态筛选在手机上占满可用宽度，窄屏纵向排列。
- 登录队列将标题、自动登录开关、统计、并发设置和暂停按钮分组排列；来源说明、错误及任务文本可断行。
- 批量工具栏将选择数量单独展示，按钮按空间换行；批量删除仍有清晰的危险操作样式。
- 手机优先使用账号卡片，展示账号名称、会话/恢复状态、凭据标记、自动恢复及操作；桌面保留表格。
- 卡片操作可换行或收进“更多”，编辑、重新登录、下载、任务/日志和删除均可访问；凭据文案不能被压成逐字换行。
- 如保留手机表格作为过渡方案，只允许表格容器内部横向滚动，页面主体不得因此溢出。
- 手机与桌面使用同一份选择状态，以 `accountId` 识别；切换布局不能清空或重复选择。
- 导入、编辑、历史及截图弹窗宽度不得超过视口，保留边距；长内容在弹窗内部滚动，底部提交、取消按钮可访问。
- 分页在手机上简化布局，保留翻页、每页数量及总数信息。

不要仅缩小字体来容纳桌面表格。若溢出源于外层布局，应同时检查页面容器和导航的宽度约束，避免用全局隐藏横向溢出来遮挡操作。

### 5.2 验收标准

手机竖屏和横屏均能完成搜索、筛选、翻页、勾选、跨页全选、批量下载和导入。长邮箱、长错误、中文及英文均不遮挡操作；桌面布局无回归。

## 6. “全选”选择全部匹配账号

### 6.1 范围与选择生命周期

| 操作/条件                  | 选择范围                             |
| -------------------------- | ------------------------------------ |
| 表头复选框                 | 当前页账号，维持现有行为             |
| “全选”，无搜索和状态筛选   | 当前全部存在的账号，包含所有分页     |
| “全选”，仅搜索             | 所有匹配搜索条件的账号，包含所有分页 |
| “全选”，仅状态筛选         | 所有匹配该状态的账号，包含所有分页   |
| “全选”，同时搜索和状态筛选 | 同时符合两者的全部账号               |
| “取消全选”                 | 清空所有分页的选择                   |

- 将按钮中文改为“全选”，英文为“Select all”；建议使用新的 `accountSelectAll` 文案键，避免旧翻译覆盖显示。
- 提示：“选择当前筛选结果中的全部账号（含其他页）”。
- 点击全选后，选择集合应准确等于本次匹配结果，以 `accountId` 去重；重复点击幂等。
- 翻页或修改每页数量保留选择；搜索或状态条件改变则清空选择，沿用现有规则。
- 全选是一次结果快照，后续新增账号或状态变化不自动加入；需要再次点击全选。
- 全选后可逐个取消，也可用表头复选框取消当前页，其余页保留。
- 已删除账号从选择中移除；五秒轮询刷新和布局切换不能丢失其他页的选择。
- 批量下载、账密导出、登录、恢复设置和删除都使用同一份已选集合；原有删除确认流程继续适用于该集合。

### 6.2 数据获取方案

不能把当前页的 `accounts` 当作全部结果；也不能只把 `pageSize` 调大，因为现有接口上限为 100。

建议新增 `GET /api/account-management/accounts/selection?search=...&state=...`：

- 提取列表接口的搜索、状态筛选为共用函数，确保两处过滤语义完全一致，包括账号编号、重复和未登录等特殊筛选。
- 返回本次请求时所有匹配账号的安全摘要及总数，字段复用 `service.list()` 的安全列表字段，不包含密码、TOTP 密钥或 Cookie。
- 摘要需满足当前批量动作使用的字段，例如 `accountId`、`authIndex`；如改为只返回 ID，则必须同时调整依赖账号摘要的动作。
- 沿用账号接口认证、禁止缓存及服务状态检查。路由位于可能匹配同一路径的动态账号路由之前。
- 一次请求生成一致的结果，避免依次获取分页期间账号变动产生漏选。大数据量时可优化为筛选快照令牌，但必须同步改造批量接口，不得静默截断选择。

前端请求期间显示 loading，禁止重复发起。记录筛选条件及请求序号；若筛选改变、页面卸载或用户取消选择，则丢弃过期响应。请求失败不得留下半套选择，保留请求前集合并提示失败。

选择应由以 `accountId` 为键的统一集合管理，当前页复选框只是该集合的视图。同步表格时防止 `selection-change` 事件把跨页集合覆盖为当前页集合；表头选中、半选状态仅基于当前页计算。

### 6.3 验收标准

- 至少准备 250 个账号，每页 20/50/100 条，全选后数量均等于匹配总数。
- 搜索、状态及两者组合分别验证；匹配零条时选择为空。
- 翻页正确回显，取消某一账号或当前页只改变对应集合，取消全选清空所有页。
- 用超过一页的匹配结果执行批量下载，ZIP 中账号范围对应全部已选账号，未匹配账号不被导出；无 Cookie 的账号沿用现有导出处理规则。
- 全选请求未完成时切换筛选或取消全选，旧响应不恢复过期选择。

## 7. 节点绑定保留与显示统计

### 7.1 统计口径

持久化绑定用于后续导入恢复；页面统计用于反映当前账号。两者分别处理：

- 删除账号后，继续保留 `store.bindings[accountKey]`，不为修正数量而清除绑定。
- 当前存在账号包括已登录/Auth 账号和已创建但未登录的账号；不能仅统计运行中的浏览器上下文，也不能仅统计有效会话。
- 账号键使用 `ProxyBindingService` 现有规则：邮箱/账号名称去空格并转小写，无名称时使用既有回退键。
- 按唯一 `accountKey` 计数，避免 Auth 与账号记录重叠导致重复；同名账号的绑定仍遵循现有按键共享语义，本次不迁移绑定键结构。
- 顶部 `bindingCount` 为当前存在账号中有 `desiredNodeId` 的唯一绑定键数量。
- 每个节点 `boundAccounts` 为当前存在账号中 `desiredNodeId === node.id` 的唯一绑定键数量。
- 统计期望绑定，不要求节点启用或绑定已经应用。`runningContexts` 继续描述运行上下文，不能替代账号绑定数。

### 7.2 实现建议

在 `ProxyBindingService` 提取当前账号的轻量键集合，复用 `list()` 的账号来源和归一化规则。`status()`、`nodes()` 以此集合过滤持久化绑定。统计路径无需解析代理或查询每个账号运行状态。

不要用账号管理页面的当前页或筛选结果计算节点数。若设置统计缓存，删除、导入、去重和 Auth 文件刷新后必须失效；优先采用读取时计算，减少陈旧状态。

账号删除完成后，下一次节点池刷新必须显示新数量；如果节点池已打开并支持自动刷新，也应更新。重新导入同一账号键后，原期望节点绑定重新可见，登录时继续沿用现有绑定应用流程。

若保留的绑定指向已移除节点，沿用现有缺失节点错误处理，不能偷偷改成直连；总数与分节点数的差异需能解释为缺失节点绑定。

### 7.3 验收标准

1. 某节点绑定 3 个存在账号，删除其中 1 个，刷新后该节点显示 2，总绑定数减少 1。
2. 检查持久化数据，被删除账号的绑定仍存在；重启服务后数量仍正确。
3. 重新导入同一账号，原绑定恢复显示，数量回到 3，不需要重新手工绑定。
4. 未登录、会话过期、人工禁用但仍存在的账号继续计数；直连节点适用相同规则。
5. 历史绑定、大小写和重复账号键不会造成重复或虚增计数；账号绑定列表与节点统计使用相同的存在性规则。

## 9. 实施结果与验证记录（2026-10-11）

- 导入弹窗新增默认勾选的“跳过已有账号”；逐行显示有效跳过状态，后端独立检查已有账号、提交时新增的同邮箱账号及重复匹配。未传 `skipExisting` 的客户端继续沿用原有规则。
