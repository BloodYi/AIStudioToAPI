# 账号自动登录与会话恢复部署

控制台的「账号管理」分页可直接访问 `/accounts`，保留 Cookie 上传、下载、批量操作、去重、切换和 `/auth` VNC 登录入口。新增邮箱/密码/TOTP 登录、凭据维护、导入、队列控制及失败诊断。所有接口沿用控制台会话鉴权。

## 运行条件

- Node.js >= 22.13；SQLite 在独立工作线程执行。
- 当前执行器使用 Linux `/proc` 与独立 POSIX 进程组进行身份验证及进程树终止。使用单个管理服务实例，不允许多个实例共享队列数据库；启动时独占锁检测重复实例。容器应启用 `init: true` 回收孤儿进程，并使用独立 PID 命名空间。跨 PID 命名空间共享队列不受支持。
- 使用与请求服务相同的 `CAMOUFOX_EXECUTABLE_PATH`。每个登录尝试单独启动一个浏览器，不共享 VNC 显示端口或请求池容量。并发默认 1，按额外 CPU/内存容量谨慎提高。
- 使用 NTP/chrony 等维护主机时间同步。验证器支持 SHA1、6 位、30 秒 TOTP；HOTP 和其他参数会明确拒绝。
- 挂载 `configs/auth`、`data` 为持久卷。自定义 `ACCOUNT_STORE_PATH`、`ACCOUNT_LOGIN_ARTIFACT_DIR` 时分别挂载相应路径。数据库及认证文件权限为 `0600`，截图目录为 `0700`；运行用户必须拥有这些目录。凭据可由后台任务读取，本版本采用受限本地明文存储。

## 配置与恢复

完整环境变量及默认值见 `.env.example`。正整数校验禁止用 `0` 关闭超时。控制台保存的并发数与暂停状态覆盖环境初始值，其他期限仍使用环境变量；队列面板显示生效来源。

登录操作返回 `202` 与任务 ID，页面关闭不取消任务。同账号只存在一个未结束任务。自动恢复只对有凭据、启用自动恢复且未人工禁用的过期账号生效。队列满时保留待恢复状态，后续扫描补入。管理员可显式登录人工禁用账号，成功后仍保持禁用和独立模型限制。

临时故障最多尝试 3 次，重试等待 30/120 秒加抖动，等待不占执行槽。密码错误、手机号验证、SSO、未知挑战等进入人工处理；使用 VNC 重新打开人工登录环境。登录成功必须确认实际邮箱及项目目标应用初始化，不调用模型生成。登录浏览器的应用本地 WebSocket 被独立拦截用于验证初始化，不进入请求连接池。

超时和取消撤销提交权限，执行器收到诊断请求后最多使用截图预算，再由监督进程终止专属进程组。无法确认清理时保留故障槽并告警，限制资源增长；监控继续重试回收，确认安全后恢复容量。重启保留已消费次数和绝对恢复期限，并按执行器 PID 与启动时间检查遗留进程；无法证明归属的 PID 不会被强杀。

凭据缺失、人工处理、队列暂停均不影响其他已有有效 Cookie。关闭 `ACCOUNT_AUTO_RELOGIN_ENABLED` 仍允许手动登录和 VNC。回滚前先暂停队列并关闭执行器，再部署旧版本；新增数据库不由旧版本读取，认证 JSON 不包含密码或 TOTP。

## 导入与诊断

CSV 列为 `email,password,totpSecret`（最后一列可选），UTF-8/BOM、引号、逗号和换行均支持，密码保持原样。预览只按规范化完整邮箱匹配；新账号需勾选创建，默认不自动登录。覆盖已有不同凭据需显式选择。预览绑定控制台会话，10 分钟过期，版本冲突按行返回失败；重复提交同一预览返回原结果。

验证器支持多条迁移链接、文本文件、普通 `otpauth://totp/` 和 Base32。缺失批次不可提交，重复批次去重，无邮箱或未知邮箱手动映射或跳过。原始导入内容仅在内存中用于有期限的预览，不进入日志或数据库。

列表及任务轮询不返回凭据或图片。点击显示才读取凭据；关闭编辑框清空前端秘密字段。截图仅点击查看后请求，响应 `no-store`；关闭预览或切换账号释放对象 URL。失败截图尽力遮罩所有输入字段，每账号最多 10 张，默认 7 天后清理；已清理图片返回 `410`。结构化终态任务默认保留 30 天，未结束或仍关联执行器的任务不清理。

停止队列及服务后，一起备份账号 SQLite 文件、认证文件和截图目录，形成一致快照。凭据备份不使用 Cookie 下载接口。恢复备份时保留单实例和 PID 命名空间条件；人工核对残留锁及故障槽，不删除活动实例的锁文件。

## 验证

`npm test` 包含队列故障注入、版本提交、迁移与 CSV 导入、标准 TOTP 向量及模拟登录页面回归测试。使用 `npm run lint` 和 `npm run build:ui` 验证代码与界面。

设置 `ACCOUNT_LOGIN_BROWSER_TEST_EXECUTABLE` 为部署浏览器的可执行文件路径，可运行 `node --test tests/account-login-browser.test.js`。该可选测试在真实 Camoufox 中使用完全本地响应及虚拟凭据，覆盖异步验证切换、隐藏旧输入框、新验证码输入类型、无二步验证、账号不匹配和应用初始化失败；未设置路径时跳过，不访问真实账号。目标应用验证通过文档响应注入隔离脚本兼容 Camoufox 的脚本沙箱，保留文档类型并移除重写后的压缩/长度头，不复用正式请求池连接。

真实登录测试脚本 `scripts/auth/testAccountLogin.js` 从标准输入读取 JSON（`email`、`password`、可选 `totpSecret`），通过独立临时账号存储运行真实队列，仅输出阶段与结果；不输出凭据或完整 Cookie，不把测试凭据写入项目。浏览器或网络环境仍可能触发 Google 人工挑战；出现未知页面时保留脱敏截图，由管理员处理，不无限重试。

2026-09-30 的授权账号验收通过邮箱及密码步骤，进入 Google Authenticator 页面；新版表单与异步验证切换促使选择器、可见性过滤及有界 DOM 轮询增加兼容处理。后续真实尝试遇到 Google 图片验证码，已按设计转人工，未完成真实登录成功及 AI Studio 会话提交验收。无二步验证、TOTP 换码和服务验证失败分支由脱敏模拟页面测试覆盖；这些结果不替代生产出口下的真实成功验收。
