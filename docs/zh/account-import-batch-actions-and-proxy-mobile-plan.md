# 账号导入、批量操作及节点池手机适配改造方案

日期：2026-10-03  
状态：待实施。本文只记录改造要求和实施方案，不代表功能已经完成。

## 1. 改造目标与已确认规则

1. CSV 新账号默认创建，勾选“跳过”才不导入；移除“创建记录，不立即登录”复选框。
2. 只有新创建的账号跟随“全局自动登录”开关：关闭时仅保存记录，开启时加入自动登录队列。
3. 已有账号保留当前凭据更新、冲突覆盖和版本校验逻辑，不因本次导入自动重新登录。
4. 账密导入预览增加批量“跳过”和批量“覆盖”复选框。
5. 账号操作区增加批量取消登录、全选、取消全选，以及每页 20 / 50 / 100 条选择。
6. 节点池页面适配手机，覆盖状态、设置、节点、订阅、账号出口绑定和各类弹窗。

“取消账号勾选”和“停止账号登录”是两个独立操作。用户提出的“批量取消勾选”实际目的包括停止输错密码后的批量登录，因此必须同时提供清空选择和取消登录任务的能力，不能只清空表格复选框。

## 2. 当前实现与问题根因

| 位置 | 当前行为 | 改造点 |

## 3. CSV 导入规则

### 3.1 新账号和已有账号的行为

| 账号情况 | 跳过 | 全局自动登录 | 结果 |
| --- | --- | --- | --- |
| 新账号 | 否 | 关闭 | 创建记录，不创建登录任务 |
| 新账号 | 否 | 开启 | 创建记录，加入自动登录队列 |
| 任意账号 | 是 | 任意 | 不创建、不更新、不创建登录任务 |
| 已有账号，无冲突 | 否 | 任意 | 按当前逻辑更新凭据，不额外创建登录任务 |
| 已有账号，有冲突，未覆盖 | 否 | 任意 | 拒绝该行更新并报告冲突 |
| 已有账号，有冲突，已覆盖 | 否 | 任意 | 更新凭据，不额外创建登录任务 |
| 行数据无效 | 默认跳过 | 任意 | 保留问题提示，不可通过批量操作强行导入 |

已有账号的更新仍调用当前 `edit()`，保留凭据变更时的任务失效处理；“不自动重新登录”不表示保留使用旧凭据的活动任务。

### 3.2 前后端调整

- 前端删除新账号创建复选框，改为展示“将创建新账号”；已有账号展示“匹配已有账号”。
- 新账号默认 `skip: false`；错误行及当前支持的未变化行继续默认跳过。
- 后端删除 `!choice.create` 的跳过条件。保留 CSV 类型、邮箱有效性、显式跳过、数据错误、重复选择和已有账号匹配校验。
- 新导入策略以后端提交时的全局配置为准。前端可显示“新账号导入后将自动登录”或“新账号仅创建记录”，但不能用前端值覆盖后端配置。
- 新账号自动任务使用 `source: "new"`，继续受全局开关、账号自动恢复开关、队列暂停、并发和容量限制约束。不能使用手动任务绕过开关。
- 同一提交采用一致的全局配置快照，并复用现有服务串行化入口；队列启动前仍检查实时配置。关闭全局自动登录后，已排队自动任务暂缓，运行中任务按当前规则继续完成。
- 保留预览的会话绑定、过期校验、版本校验、单次提交结果缓存和逐行错误汇总。

### 3.3 创建成功与入队失败分开报告

直接改成 `create(input)` 会遇到一个现有边界：开启自动登录且队列满时，`create()` 在保存账号之前抛错。建议本次改造明确采用“先保存记录，再尝试自动入队”的策略：

1. 验证并创建账号记录，统计 `created`。
2. 如果全局自动登录开启，尝试创建自动登录任务。
3. 队列满等可预期的入队失败不回滚已创建记录；单独显示“记录已创建，自动登录未入队”的行级原因，用户可稍后批量重新登录。

保留 `created / updated / skipped / failed / errors` 的原有记录导入统计，可新增 `loginQueued` 和 `loginWarnings` 表示入队结果。`failed` 表示记录导入失败，不把同一行同时统计为创建成功和导入失败。登录任务执行失败由任务状态展示，不混入导入失败数。

网络重试或重复点击不能重复创建记录、重复入队；继续使用预览提交结果缓存。完成后的同一预览不支持重新勾选再提交，需重新解析预览。

## 4. 导入预览的批量跳过与覆盖

### 4.1 交互要求

在“跳过”和“覆盖”各自的列标题或预览工具栏增加批量复选框：

- “全部跳过”：选中则勾选全部可操作行；取消则取消全部可操作行的跳过。
- “全部覆盖”：选中则允许全部已有账号行覆盖；取消则取消这些行的覆盖许可。
- 部分行选中时，表头显示半选状态；逐行修改后立即同步表头状态。
- 无可操作行时禁用对应批量复选框。

批量范围是本次预览的所有行；如果未来预览分页，仍覆盖整个预览，不能仅修改当前可见页。

### 4.2 边界与优先级

- 错误行和不可导入的未变化行保持跳过并显示原因；“取消全部跳过”不得解除这些行的限制。
- 新账号没有可覆盖的记录，“覆盖”对其不适用，复选框禁用或不展示。
- 已有账号行可勾选覆盖，包括当前无冲突行；覆盖只表示允许导入的字段替换已有值，不清空 CSV 未提供的字段。
- 同一行同时勾选覆盖与跳过时，以跳过为准，不写入数据。
- 不再提供“全部创建”，新账号默认创建。
- 提交期间禁用导入选项和提交按钮，避免重复提交和统计与选项不一致。

## 5. 账号选择和分页

### 5.1 操作区按钮

| 按钮文案 | 操作范围 | 是否影响登录任务 |
| --- | --- | --- |
| 全选本页 | 当前搜索、筛选条件下的当前页账号 | 否 |
| 取消全选 | 清空全部已选账号，包括其他页保留的选择 | 否 |
| 批量取消登录 | 所有已选账号的可取消登录任务 | 是 |

“全选”采用本页范围，避免误解为全库选择，按钮使用“全选本页”。保留当前跨页选择能力，工具栏显示“已选 N 个（含其他页）”；所有批量动作均作用于全部已选账号。

- 全选本页应幂等，不因第二次点击反向取消选择。
- 取消全选应调用表格清空选择能力，并同步清空用于批量请求的选择状态。
- 翻页和调整每页数量保留已选账号；更改搜索或状态筛选时清空选择，防止隐藏账号被误操作。
- 自动轮询刷新不得丢失选择或重新选中已取消选择的账号；按稳定 `accountId` 保存选择。
- 账号删除后移除对应选择，选中计数与实际批量请求一致。
- 后端批量操作应重新读取账号和任务状态，不能依赖跨页缓存的 `currentTaskId`。

### 5.2 分页要求

- 提供每页 20、50、100 条，默认 20 条。
- 使用响应式 `pageSize`，列表请求显式携带 `page`、`pageSize`、搜索和状态筛选。
- 修改每页数量时回到第 1 页，避免停留在越界页。
- 删除等操作导致当前页越界时，回到最后一个有效页；总数为零时保留第 1 页空状态。
- 避免页码和页大小事件重复触发同一加载；复用现有刷新序号保护，防止旧请求覆盖新页数据。
- 不改变登录历史分页，也不改变导入账号映射时内部拉取每页 100 条的逻辑。

## 6. 批量取消登录

### 6.1 目标行为

用户发现密码输错后，选中相关账号并点击“批量取消登录”，应停止这些账号已排队、等待重试和正在运行的登录任务，同时停止当前页面批量登录流程对这些账号尚未发出的请求。

- 可取消任务状态为 `queued`、`retry_wait`、`running`。
- 已成功、已失败、已取消或没有任务的账号报告为“无需取消”；不能撤销已经成功写入的登录结果。
- 保留账号记录和凭据，不删除账号，不清空密码。
- 不影响未选中的账号，不暂停整个队列，不关闭全局自动登录。
- 操作后保留账号选择，方便修正凭据和重新登录；清空选择由“取消全选”单独完成。
- 取消操作可重复执行，单个账号异常不阻断其他账号处理。
- 显示取消成功、无需取消、执行器仍在停止及失败的数量和原因。后端已标记取消不等于浏览器进程已退出，界面不能过早宣称全部停止。

### 6.2 建议接口与执行顺序

建议新增 `POST /api/account-management/accounts/batch/cancel-login`：

```json
{
  "accountIds": ["account-id-1", "account-id-2"]
}
```

响应返回每个账号对应的处理结果和汇总，区分取消、无需取消、停止中和失败。复用已有身份验证、服务串行化和任务取消能力；限制请求数量，校验并去重账号 ID。现有单任务取消接口保留。

1. 前端对选中账号及当前批量登录流程建立稳定的 ID 快照；点击取消后，停止向被取消账号继续发送登录请求。
2. 对已发出的请求等待其明确结果或做状态对账；不能认为 `AbortController` 中止网络等待就代表后端没有创建任务。确保这些已发出请求创建的任务也被后续取消覆盖。
3. 后端按账号 ID 读取实时活动任务，串行写入取消状态、失效执行结果 token、清空当前任务关联并保存。
4. 使用现有队列的执行器终止和进程组回收机制停止运行中的浏览器；避免在持有服务串行锁时等待再次需要同一锁的队列回调。
5. 刷新账号列表和任务状态；若执行器仍在退出，继续展示停止中并跟踪结果。

当前 `batchLogin()` 逐个调用 `login()` 且每次刷新，应改为可中断的批次流程，并在批次结束统一刷新。取消按钮不能被普通提交中的统一 `busy` 状态禁用，否则恰好在批量提交时无法停止；使用独立的登录提交和取消状态防止重复操作。

### 6.3 防止取消后自动重启

必须给被显式取消的活动任务所属账号留下“需要手动继续”的恢复状态，不能继续设为可被 `scanRecovery()` 自动扫描的 `idle`。建议复用现有 `manual_required` 状态，并在任务历史保留“用户取消”的原因。

- 不修改账号的 `autoRecovery` 持久化开关，也不修改全局配置。
- 轮询、刷新、服务重启及全局开关关闭后再开启，不得使本次取消的任务自动重新入队。
- 修正凭据后由用户主动点击重新登录或批量重新登录恢复；保留现有手动登录入口和配置规则。
- 对无活动任务账号只报告无需取消，不额外改变其恢复策略。
- 运行中旧任务的迟到成功、失败、重试消息不能覆盖取消状态或写入 Cookie。
- 同一账号停止尚未完成时，不启动第二个浏览器登录执行器；后续手动登录需等旧执行器释放。

建议将这一显式取消语义同步到单任务取消，避免单个取消和批量取消表现不同。实施时需审查 `failTask()`、队列 `finish()`、token 校验和状态持久化，验证异步回调不会将 `manual_required` 改回 `idle`。

## 7. 节点池手机适配

### 7.1 适配范围和布局

以 768px 以下采用手机布局为建议起点，最终根据实际容器宽度验证：

- 页面和卡片允许收缩，减少手机端留白；状态摘要换行或采用两列布局，长版本号和错误信息可换行。
- 移除或覆盖设置输入框的 360px、账号搜索的 220px、选择器的 140 / 180px 等固定宽度；手机端占满可用宽度。
- 工具栏按钮换行，重要操作保持可见，不依赖横向滚动才能点击。
- 手机端节点列表、订阅列表和账号绑定列表改用卡片或紧凑列表；桌面保留表格，共用同一份数据和操作逻辑。
- 卡片保留选择复选框和全部现有操作；不能通过隐藏列让手机端失去测试、编辑、删除、刷新订阅、保存绑定或应用能力。
- 弹窗宽度不超过视口减去两侧留白，内容过高可纵向滚动，底部操作可触达；手机端表单标签改用顶部排列或合理缩短宽度。
- 账号绑定分页在手机端拆分总数、页大小选择和前后页按钮，避免整个分页条超宽。
- 触控入口建议至少 44px 高；长节点名称、邮箱、订阅 URL、IPv6 地址和错误信息允许换行或展开。

### 7.2 手机卡片信息要求

| 区域 | 卡片中必须可见或可展开的信息与操作 |
| --- | --- |
| 节点 | 名称、类型、状态、延迟、出口 IP、绑定数；地址和本地端口可展开；测试、编辑、删除 |
| 订阅 | 名称、已脱敏地址、节点数、最近刷新时间；刷新、删除、批量选择 |
| 账号绑定 | 账号、当前来源、期望节点、绑定状态、在途数；选择节点、保存绑定、应用和批量选择 |
| 设置与状态 | Mihomo 就绪情况、节点池启用状态、节点及绑定数量、测试 URL 和其他现有设置 |

继续显示已脱敏的订阅地址，不因手机布局泄露原始敏感数据。节点池账号绑定已有 20 / 50 / 100 分页，保留其行为，只调整手机呈现。

### 7.3 验收尺寸

覆盖 320、375、390、414、768、1280px 宽度和手机横屏；同时验证独立节点池路由及实际父级容器。要求页面主体无横向溢出，弹窗不越界，主要操作无需页面横向拖动即可完成，桌面布局正常。

## 9. 测试与验收清单

### 9.1 CSV 与批量预览

- 全局关闭：导入 19 个合法新账号且不逐行勾选，结果为创建 19 个、跳过 0 个、没有新登录任务。
- 全局开启：同样输入创建 19 个账号并尝试自动入队；正常容量下每个新账号只有一个自动任务。
- 混合新账号和已有账号：仅新账号自动入队，已有账号更新不自动重新登录。
- 跳过优先于覆盖；冲突未覆盖时仍拒绝更新；无效行不因取消全部跳过而被提交。

### 9.2 账号选择、分页与取消

- 全选本页只选择当前页；跨页后选择保留；取消全选清空全部页的选择。

- 全局自动登录开启且会话过期时，取消后经过多轮扫描和服务重启仍不自动重试。
- 批量登录提交尚未结束时可点击取消；选中账号尚未发送的请求停止，已在途请求创建的任务也被取消。
