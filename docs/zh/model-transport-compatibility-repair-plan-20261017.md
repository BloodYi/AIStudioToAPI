日期：2026-10-17（Asia/Shanghai）。状态：待实施。本次只编写实施方案，不修改运行代码、创建分支、启动生产实例或部署服务。

本方案以当前 `main` 为开发基线，选择性复用 `archive/makersuite-protocol-1dc1e30` 的桥接代码。对于目标模型的上游路径选择，本方案取代此前“Gemini 4 Argon 必须继续走旧 ProxyUnaryCall”的约束；此前方案中的账号隔离、权益真实性、取消、错误分类和数据保护要求继续有效。

### 1.2 本轮目标

1. 3.7 Flash 保留旧 Proxy RPC、原始模型 ID 和已验证的真实流式行为。
2. Argon 使用直接发往 MakerSuiteService/GenerateContent 的桥接，保留当前真实权益检查。
3. 四类 API 的 JSON/SSE 外形保持兼容；桥接的客户端 `real` 请求明确转为缓冲输出。
4. 缓冲生成超过 60 秒仍可在完整生成预算内完成，超时和取消真正终止对应上游工作。
5. 其他模型首期维持当前行为，后续逐个验证后迁移，不静默改动额度、模型名称或调用路径。

本轮不移植参考项目的双槽协调器、账号等级 UI、额度估算体系或保活策略，不新建或修改用户已保存的 Build App，不自动修改 NewAPI 渠道。

## 3. 统一模型路由策略

### 3.1 首期默认规则

| 清理后的精确模型 ID | 有效传输     | 上游能力                                  | 首期行为                                        |
| ------------------- | ------------ | ----------------------------------------- | ----------------------------------------------- |
| `gemini-3.7-flash`  | `legacy`     | 沿用原 ProxyUnaryCall / ProxyStreamedCall | 继续现有请求与流式模式，不本地映射到 3.8        |
| `gemini-4-argon`    | `makersuite` | 直接 MakerSuite GenerateContent，响应缓冲 | 使用新桥接、实时权益和已核验账号集合            |
| 其他模型            | `legacy`     | 沿用当前实现                              | 验证后可显式切为 `makersuite`，不在本轮全量切换 |

`legacy` 和 `makersuite` 是本项目的传输策略标识，不是客户端 API 格式，也不是 Google 会员等级。

建议新增 `src/core/ModelTransportPolicy.js`，返回同一份不可变策略：清理后的模型、有效传输、是否增量输出、请求的流模式、有效流模式、超时类别。RequestHandler、浏览器 RPC 分派及调度日志共同使用，不能各写一套 Argon 判断。

### 3.2 配置与请求快照

建议新增 `MODEL_TRANSPORT_POLICY`，JSON 示例：

```json
{
  "gemini-3.7-flash": "legacy",
  "gemini-4-argon": "makersuite"
}
```

这是拟新增配置，不是当前版本已支持的选项。未配置时使用 3.1 的默认规则；用户提供的精确模型条目覆盖默认条目，其他模型仍走默认 legacy。仅接受这两种传输值，拒绝无效 JSON、原型污染键、未清理的指令后缀及通配匹配。

首期配置按重启生效，通过现有配置定义、环境加载、持久化及重启机制统一接入，不只在某个构造器读取环境变量。每个逻辑请求在接收时固定策略版本，排队、重试、抗截断后续轮次及浏览器分派保持一致；已开始的请求不能因为配置变化中途改路。

模型后缀和抗截断前缀沿用当前解析顺序，再按精确 ID 选择路径。`gemini-4-argon-real` 必须进入 Argon 的桥接规则，不能把所有 `gemini-4-*` 都当成 Argon。模型列表只有在具备实际资格并验收后才展示为可用。

### 3.3 不自动跨通道重试

首期不实现“失败就换另一条路径”的自动模式。400、401、403、404、429、超时和断线均不能无条件触发另一次生成。

尤其不能把旧路径 429 当成自动切桥接的信号，或把结果不确定的桥接超时重放到旧路径。已确定模型走哪条路径，就按该路径处理本次调用的错误；变更策略后由新的请求重新验收。

如果 Google 日后完全撤销旧通道，而 3.7 在新通道仍无入口，应明确标记其不可用，保留历史用量，不偷偷改成 3.8 或声称独立额度已迁移。若以后加入自动降级，应另行设计明确拒绝、未产生生成副作用时的判据。

## 4. 两条请求链路与浏览器所有权

```text
OpenAI Chat / Responses / Anthropic / Gemini native
  → 现有格式转换与统一模型策略
  → 原有账号资格、排队和 request/attempt
  → 同账号 Build 客户端及宿主页
      ├─ legacy：页面原生 WAA + 原 Proxy RPC → 原响应解析
      └─ makersuite：拦截目标生成 RPC
           → codec 转换 → 为新请求生成 WAA
           → 同账号 MakerSuiteService/GenerateContent
           → 编解码并封装现有客户端可读的响应
  → 原有 JSON / SSE 格式输出
```

### 4.1 单一分派点

由一个浏览器分派层识别精确 Google origin、RPC pathname、HTTP 方法和载荷首项中的生成模型/方法，再调用 legacy 或 bridge handler。不要同时安装两套抢占同一个 ProxyUnaryCall 的 route，依赖注册先后来决定行为。

- legacy 不改 URL、正文、WAA、认证和模型 ID；保留现有明确授权的 header-only 权益处理能力。
- makersuite 只截获策略指定的生成请求，不能误拦模型目录、文件、embedding、countTokens 或其他服务。
- 桥接自己的 GenerateContent、权益查询及令牌服务请求不能再次被桥接，也不能作为本模块自我学习认证的来源。
- 如复用归档的本地关联标记，不得把该标记发往 Google；legacy 出站 wire 必须保持原样。

### 4.2 权益、认证与 WAA

继续使用每个账号、页面和文档独立的权益上下文。Argon 必须同时满足已核验账号集合与实时付费权益；配置 `[0]` 只声明可参与验收，不授予权限。unknown 可受限预检，不能生成；failed、ready-free 与账号登录过期继续分开处理。

桥接认证与权益读取使用当前宿主页真实上下文：

- 服务 API Key 排除令牌服务 Key、客户端传入的 Key 和本模块自产请求；不恢复 `mb.jK` 等固定属性读取。
- Authorization、authuser、Cookie、tier 和 ext 不跨账号、会话或文档复用。ext 保持不透明，缺失不伪造。
- GenerateContent 必须带上当前页面提供的真实权益上下文，不能只恢复归档中的认证头。
- 对转换后的目标路径/载荷重新生成 WAA，不把旧 proof 用在新请求上，也不在生成 proof 后改 RPC 名称或内层正文。
- 归档使用的页面内部接口需能力检查；模块、令牌服务或认证未就绪时受控返回，不执行猜测性探测生成。

保留当前 Camoufox 主 realm 执行及文档通知修复。标准 Firefox 的 binding 路径和当前 Camoufox 的无敏感字段 console 通知路径都需验证，不能仅在标准 Firefox 中通过就宣称生产可用。

缓存和活动调用绑定 `authIndex + sessionVersion + browserGeneration + page/document + request/attempt`。导航、会话替换、context 重建、关闭及浏览器恢复均使旧状态失效；旧实例不能清除新实例资源或唤醒错误的队列。

## 5. 流式语义与超时修复

### 5.1 按真实传输能力选择有效模式

客户端 `stream:true` 表示需要 SSE，不意味着上游有增量数据。首期桥接仍会先收完整上游响应再封装返回，必须明确视为缓冲传输。

| 客户端要求                              | legacy                     | makersuite 桥接                                                          |
| --------------------------------------- | -------------------------- | ------------------------------------------------------------------------ |
| 非流式                                  | 原有 JSON                  | 等完整生成后返回原有 JSON                                                |
| fake SSE                                | 原有 fake                  | 完整结果转换为兼容 SSE                                                   |
| early SSE                               | 原有 early                 | 保留提前开始及心跳，结果到达后输出正文                                   |
| real SSE，含 `-real`                    | 已验证模型保持真实增量路径 | 有效模式转为 fake；允许用户显式选择 early，不宣称实时增量                |
| Gemini `:streamGenerateContent?alt=sse` | 原有行为                   | 保留客户端 wantsStream/SSE；内部提前选择缓冲生成路径并清除不再适用的 alt |

在生成页面 WAA 之前确定内部方法及有效模式。桥接首期优先复用 unary 包装，以减少伪 streamed envelope；归档对 streamed 的支持可留作兼容，但不能因此重新使用 55/60 秒的整次生成上限。

四类入口必须共用策略；非流式调用不能提前写 SSE，错误发生在写头前时仍返回正确 HTTP 状态。early 已写头后的错误按协议发送错误事件并结束。日志/状态同时记录请求模式和有效模式。

### 5.2 已知的多层限制

| 层级                                 | 当前或归档值                                             | 必须处理的问题                                             |
| ------------------------------------ | -------------------------------------------------------- | ---------------------------------------------------------- |
| 归档 MakerSuiteBridge                | 普通 295000 ms；streamed 55000 ms                        | 不能因外层曾是 streamed 就把缓冲生成限为 55 秒             |
| 当前 RequestHandler                  | STREAM_CHUNK 默认 60000 ms；FAKE_STREAM 默认 300000 ms   | 真实增量空闲超时不能作用于桥接生成等待                     |
| 当前浏览器 `scripts/client/build.js` | 首响应等待硬编码 300000 ms，正文读取另有超时             | 服务端调大配置不会自动突破浏览器上限，需统一预算与能力检查 |
| 当前配置定义                         | STREAM_TIMEOUT_MS、FAKE_STREAM_TIMEOUT_MS 最大 300000 ms | 如支持更长预算，配置验证、UI、持久化和客户端必须一起修改   |
| 网关、NewAPI 和调用方                | 各自独立                                                 | 最短的一层决定实际可等待时间，不能只修改桥接               |

参考项目把桥接及浏览器等待放宽到 600000 ms，消息队列默认也为 600000 ms，但部分读取和 Gemini fake 首响应仍是 300000 ms；其短请求通过不证明所有入口都支持十分钟。不得原样复制一个 600000 常量后宣称问题解决。

### 5.3 本轮预算约定

首期沿用现有缓冲配置 `FAKE_STREAM_TIMEOUT_MS`，默认 300000 ms；`STREAM_TIMEOUT_MS` 默认 60000 ms，继续表示已验证 legacy real 的增量空闲等待，不缩短原有真实流式的持续时间。

对缓冲路径建立固定的生成 deadline，覆盖认证等待、WAA、上游 fetch、完整正文读取及转换。服务端用单调时钟记录 deadline；跨页面/客户端传递剩余毫秒，不混用不同 realm 的 `performance.now()` 基准。

默认预算示例：

| 环节             | 默认预算安排                                                         |
| ---------------- | -------------------------------------------------------------------- |
| 缓冲结果外层等待 | 300000 ms                                                            |
| 新桥接上游调用   | 最多 295000 ms，预留约 5 秒结算/传输时间，并扣除前面已经消耗的时间   |
| 认证就绪等待     | 单独短上限，例如 10000 ms，同时受剩余生成预算约束                    |
| 浏览器客户端     | 覆盖剩余完整生成预算；先于外层结束的上游必须返回明确错误             |
| 排队等待         | 保留调度器独立期限，不冒充模型生成时间                               |
| 网关/调用方      | 按排队期限、生成预算和必要余量核对；未写响应时尤其需要足够的等待时间 |

这是一套总预算约束，不是每层各给一次全额预算。重试消耗剩余预算，心跳不重置 deadline，单纯收到内部“仍在处理”事件也不算模型进展。预算已不足时立即受控超时，不再发生成请求。

early/fake 的 SSE 心跳只维持连接，不生成假的正文 delta，不延长上游硬时限。队列首响应和桥接结果等待均使用缓冲预算；已缓冲的响应在传输到客户端时，还需有剩余预算及关闭检测。

抗截断的后续上游调用保留现有轮次约束，并明确其整体期限与单次预算的关系，不能借继续生成无限重置等待。

如后续支持 600000 ms，应同步提升配置允许范围、浏览器请求预算、服务端等待和外部代理/客户端配置，给最内层留出提前取消的余量。不能让上游与网关都在同一个 600 秒边界竞争超时。

### 5.4 浏览器客户端兼容

通过内部 `proxy_request` 传递传输策略、有效模式和剩余预算；这些内部字段不进入 Gemini 正文或 Google 请求头，不能采信外部客户端伪造的预算/会员声明。

客户端需验证和使用这些字段，并通过现有握手报告能力或版本。旧 Build 客户端未支持新字段时，应保留其已知上限；高于旧上限的配置须明确报告不支持，不能表面配置成功、实际仍被 300 秒取消。

优先复用现有运行时客户端安装/分发机制。若确需更新客户端，应在文档说明并验证当前自建 App 的兼容性，不创建新 App，不未经授权修改用户已保存的应用。默认五分钟方案不能以“需要用户自行改 App”作为未经验证的前提。

## 6. 取消、结算、错误和额度

每个 request/attempt 对应独立的页面桥接记录、AbortController、队列和租约。客户端断开、用户取消、deadline 到达、导航或 sessionVersion 替换时：

1. 标记该 attempt 不再接收输出，通知页面终止新的 GenerateContent fetch。
2. 同时取消原生被拦截请求、reader 及关联定时器；不是仅让 Promise.race 提前返回。
3. 等待上游取消结算或进入受控的有限清理流程，再释放占用；不能假定收到取消指令就已经没有上游工作。
4. 最多结算和释放一次；迟到响应不能输出到新 attempt 或删除新记录。
5. 结果不确定时不自动重放生成。保留有界资源和异常日志，不无限等待卡死浏览器池。

保留主分支已经实现的受控错误返回：

- 认证/权益未就绪：本地明确错误，不导致 Express 异步拒绝、子进程退出或账号池过期。
- 上游 400/404：保留结构化错误，区分参数不支持与模型入口不存在；不跨通道盲试。
- 上游 401：结合当前会话及真实认证错误判断；旧会话迟到事件不能禁用新会话。
- 上游 403 / RPC Code 7：模型×账号×传输的资格问题与全账号风控分开，不仅凭一个 403 标 IP 风控。
- 上游 429 / limit=0：保留原始错误、模型及实际路径，不清额度，不把 paid 等同于有配额。

本轮不重构本地配额体系。保留 3.7 的原始模型 ID、历史统计和已有冷却；Argon 未知日额度继续显示未知。日志应附带传输维度，以便追查路径差异；不能在切换路径时自动重置持久状态或宣称额度通用。若旧通道失败记录阻碍新通道派发，应按明确的错误来源与路径作用域失效该资格判断，不删除历史用量、不清除真实限流来制造成功。

- 构建共享权益与单一浏览器分派，验证新 proof 和正确服务 Key，禁止直接全局启用归档 route。

阶段通过条件：其他模型 wire 不变；3.7 不触发新 GenerateContent；Argon 的新调用确实为 MakerSuite GenerateContent，不是仅打印桥接日志。

### 阶段 B：缓冲模式、预算与取消

- 四入口 stream/non-stream 选择一致路径，`-real`、全局 real、Gemini `alt=sse` 均按有效能力处理。
- 移除桥接 streamed 的 55 秒整次生成上限；缓冲等待不使用 60 秒增量空闲计时。
- 贯通固定 deadline、浏览器取消、队列和租约结算；保留 early 的协议行为与保活。

阶段通过条件：结果超过 60 秒但仍在预算内时成功，超过预算或取消后上游实际停止，且没有重复派发或孤儿活动调用。

### 阶段 D：单账号真实上游验收

先读取最新生产状态，不能机械沿用旧报告。按当前对照部署记录，原 `aistudio-bero` 已停止、参考实例 `ais2api-bero` 正在使用同一份 Cookie；任何真实验收都必须先备份当前活跃实例并停止它，确认浏览器关闭后，再启动本项目。不能同时启动两个实例使用同一份 Cookie，也不能用旧数据库覆盖当前数据。

本阶段需有实际部署/切换授权；本文档本身不执行这些动作。保留当前数据与认证，构建带源码版本的新镜像；先保持 Argon 未开放，验证管理、普通调用及受控预检错误，再临时指定同账号进行目标验收。

验收顺序：

1. 普通模型短调用，确认服务、认证、响应格式正常。
2. 3.7 非流式和 real SSE：确认原始 ID、旧 Proxy RPC、正文/usage/结束事件，没有转入桥接或本地改成 3.8。
3. Argon 一次非流式：HTTP 200、有实际生成正文/usage，实际为 MakerSuite GenerateContent，新权益来自当前账号，没有通道回退。
4. 第一次成功后，再验证 Argon fake/early、客户端 real 降为缓冲、全局 real、后缀和原生 SSE。
5. 确认冷启动首次调用、文档导航后首次调用、context 重建、工具后续轮次、客户端取消；长等待主要由受控 fixture 证明，真实长请求另行按授权最小范围验证。

失败时保留脱敏证据并停止扩大测试，不重复轮换、清额度或绕过权益；根据已知成功状态恢复原运行方案，保持一次只运行一个使用该 Cookie 的实例。
